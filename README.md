# 读空气（astrbot_plugin_context_recall）

两条互补的链路，共用一份聊天流水和一套配置：

1. **发送前审查** —— 生成的消息先扣下来判一遍，不合逻辑就打回重写，重写的再审，始终不过就**拦截不发**；
2. **发送后撤回** —— 说出去的话如果不合语境，自己撤回来。

---

## 一、发送前审查（过审才发）

```
LLM 生成回复
   ↓
截下来（on_decorating_result，还没发出去）
   ↓
过滤：非 LLM 结果 / 带图片语音 / 太短 / 含工具调用字符 → 放行
   ↓
判：OK 还是 BAD|理由          ← 约 0.6~1.3 秒，5 个 token
   ├─ OK → 照常发出
   └─ BAD → 打回重写 → 重写的**再判一遍**
              ├─ 通过 → 用重写后的文本发出
              └─ 仍不过 → 再重写（到上限为止）→ 仍不过 → 拦截，不发送
```

**判什么**（只有这四种才算「明显不合逻辑」）：

| 类型 | 例子 |
|---|---|
| 答非所问 | 对方问「北京要带伞吗」，回「上海今天下雨了」 |
| 自相矛盾 | 同一句里前后冲突，或与刚确认的事实冲突 |
| 事实错乱 | 编造与上文直接冲突的事实 |
| 语无伦次 | 句子断裂，读不出完整意思 |

**不判什么**：观点不同、语气不好、不够有趣、有点啰嗦、答得不够全面 —— 这些一律放行。

### 工具调用类消息不动

**两层拦截，命中任一层就整条原样发出（不审、不改写、不拦截）：**

1. **消息链里带结构化组件** —— `At`（@某人）、`Reply`（引用回复）等。这些是 `reply_to` / `@某人` 这类工具调用的产物，改写会破坏寻址目标。
2. **文本里带机器语法** —— `<tool>`、`function_call`、`<|python_tag|>`、`tool_calls`、`tool_use`、`{"arguments": {...}}`、`Action Input:`、`Observation:`、`【工具调用】`、`mcp__`、`antml:`、`[CQ:at,qq=...]`、`[At:123456]`、`[Reply:...]`、`reply_to`、`@123456789`（纯数字提及）。

想连引用回复也一起审，把 `precheck.skip_structured` 关掉即可 —— 那时 `@` 和引用组件会被保留，只改文字部分。

### 为什么快

| 手段 | 效果 |
|---|---|
| 裁决只要 `OK` / `BAD\|理由` | 输出约 5 个 token，实测 0.6~1.3 秒 |
| 重写只回消息本身（不解释、不加引号） | 一次往返搞定 |
| 上下文只带 10 条、每条截 120 字 | 输入短，prefill 快 |
| 正常消息只花一次调用 | 只有出问题才有第 2、3 次 |
| 太短（<2 字）、语气词（嗯/好/哈哈）直接跳过 | 省掉无意义的调用 |
| 超时/报错一律放行 | 宁可发出去，也不因为审查吞消息 |

## 二、发送后撤回

```
有人接话 → 找出机器人自己在 100 秒内说的最后一段话
        → 看现场反应：有人「？」→ 高优先级；随口「嗯」→ 放过
        → 模型裁决 {"verdict":"recall|keep","confidence":..,"reason":..}
        → 置信度 ≥ 0.78 且没超配额 → delete_msg 撤回
```

只撤这 7 类：误解意思 / 认错对象 / 话题已过 / 场合不合 / 冒犯越界 / 重复矛盾 / 模板泄漏。
冷场、平淡、没人接 —— 一律不撤。

## 三、安全阀

| 环节 | 阀 | 默认 |
|---|---|---|
| 审查 | 重写次数 | 最多 1 次（可配 0~3） |
| 审查 | 超时放行 | 12 秒内没结果就放行 |
| 审查 | 每小时上限 | 200 条后本小时直接放行 |
| 审查 | 演练模式 | `precheck.dry_run=true` 只记日志不拦 |
| 撤回 | 时间窗 | ≤ 100 秒（QQ 只允许 2 分钟内撤回） |
| 撤回 | 配额 | 3 次/小时、12 次/天、同会话冷却 5 分钟 |
| 撤回 | 演练模式 | `dry_run=true` 只记日志不撤 |

## 四、指令

| 指令 | 说明 |
|---|---|
| `/air` `/空气` | 状态：开关、配额余量、审查统计（审了几次/重写几次/拦了几条） |
| `/air audit` | 最近 8 条判定，`[发]` 前缀是发送前审查，`[撤]` 是发送后撤回 |
| `/air test` | 就地试跑一次**撤回**判定（不真撤，仅管理员） |

## 五、配置要点

WebUI → 插件 → 读空气。

### 共用

| 配置 | 默认 | 说明 |
|---|---|---|
| `enabled` | true | 总开关 |
| `scope.recall_groups` / `recall_private` | true / true | 生效范围（两条链路共用） |
| `scope.only_sessions` / `ignore_sessions` | 空 | 白/黑名单 |

### 发送前审查 `precheck.*`

| 配置 | 默认 | 说明 |
|---|---|---|
| `enable` | true | 总开关 |
| `dry_run` | false | 演练（只记日志不拦截） |
| `max_attempts` | 1 | 打回重写次数；0 = 只审不重写 |
| `history_count` | 10 | 审查时带多少条记录 |
| `max_line_chars` | 120 | 每条记录截多长 |
| `min_chars` | 2 | 少于这么多字不审 |
| `timeout_seconds` | 12 | 单次审查超时（超时放行） |
| `max_checks_per_hour` | 200 | 熔断 |
| `skip_structured` | true | 带 @ / 引用回复的消息整条放行 |
| `skip_tool_patterns` | 内置 | 工具调用 / 寻址语法字符表 |
| `judge_prompt` / `rewrite_prompt` | 内置 | 可自定义 |

### 发送后撤回

见 `timing.*` / `decision.*` / `limits.*` / `signals.*`。

## 六、依赖与限制

- **协议端**：需要 `get_group_msg_history` / `get_friend_msg_history`（NapCat、LLOneBot、Lagrange 都支持）。
- **只管管线内的回复**：走 AstrBot 正常回复流程的消息都会被审；**插件直接调 `context.send_message` 发的消息（例如「主动消息」插件）不经过这里**，无法拦截。
- **流式输出**：`streaming_response=true` 时流式结果不走这个钩子（AstrBot 自身也这么限制），审查不生效。
- **被拦截的消息不会补发**：按设计就是「不发」。想查原因看日志或 `/air audit`。
- **需要撤回权限**：机器人只能撤自己 2 分钟内的消息。

## 七、安装

```bash
cd ~/.astrbot/data/plugins          # Windows: %USERPROFILE%\.astrbot\data\plugins
git clone https://github.com/Leaveing00001/astrbot_plugin_context_recall.git

# 或者手动：把仓库里的 main.py / core/ / _conf_schema.json / metadata.yaml
# 放进 data/plugins/astrbot_plugin_context_recall/（目录名必须一致）
```

克隆后在 WebUI 插件页重载（或重启 AstrBot）即可。没有第三方依赖，不用 pip install。

## 八、已知取舍

- 审查会**增加 0.6~1.3 秒**的发送延迟（一次短调用）。这是「过审才发」的固有成本。
- 判定是二值的（OK / BAD），没有置信度；为了速度牺牲粒度，用「重写 + 再审」吸收噪声。
- 重写只做最小修正（原句 + 问题描述），不带完整人格提示词。
